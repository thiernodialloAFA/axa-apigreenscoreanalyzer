The API Green Score calculation and Creedengo scan are independent; both feed the same JSON reports.

Creedengo — What is it for?

Code analysis

Detects eco-design anti-patterns in Java, Python, and C# source code

GCI rules

Identifies unnecessary SQL queries, calls inside loops, poorly released resources, and other avoidable costs

And in this repo?

SonarQube + Creedengo plugin, launched with --creedengo or creedengo-analyzer.sh

Result

Score /100, grade, violated rules, and report

scripts/start.sh — Run an analysis

The script orchestrates an end-to-end green analysis (API Green Score + Creedengo): it prepares the target, runs the checks, and produces the dashboard and reports

Targets & specifications

Parameters to specify one or more APIs, their OpenAPI contracts, and authenticated access when required

Source & execution

Parameters to choose the stack, provide source code, start the API locally, and enable diagnostic traces

Code quality & architecture

Options to run Creedengo and check ADRs, including from a Git repository or subdirectory

Score & integrations

Context parameters for scoring, geographic proximity, cloud footprint, and sending results to SobriIT

Values can come from CLI options or environment variables, depending on the parameter. Example: bash scripts/start.sh --stack java --build-and-run --source-dir ./my-app --creedengo

Integrating an API Green Score + Creedengo pipeline into your project

pr-green-api-axa.yml — Green API pipeline

  • Setup : JDK 17+, Maven, Python
  • Clone analyzer: Fetches the analyzer repository
  • Run: scripts/start.sh with parameters
  • Analysis: Creedengo, Green Score, OpenAPI
  • Variables: Targets, Swagger URLs, stack (auto/java/dotnet)

Recommendations for integrating the pipeline

Prepare variables

Set the targets, Swagger URL, stack, execution profile, build options, etc.

TARGETS · SWAGGER_URL · STACK · BUILD_AND_RUN

Accessible Swagger

Check that the path is accessible from the CI agent: authentication and HTTP 200 response

/swagger · /v3/api-docs

Module names

Check Maven or Gradle module names and target the right subdirectory before running the pipeline

Secrets management

Store tokens and credentials in CI secret variables, never in YAML or logs

API_TOKEN · CLIENT_SECRET · etc

API Green Score — Rules refresher

Performance

Pagination (DE11), filtering (DE08), compression (DE01)

Caching

ETag/304 (DE02/DE03), delta queries (DE06)

Scalability

Range/206 (Partial Content), Binary formats (Protobuf)

Architecture

Event-driven (AR01), Runtime Proximity (AR02), Single API (AR03)

Cloud & observability

Scalable Infra (AR04), Cloud Footprint (AR05), Health/Metrics (LO01)

How the report is generated

flowchart LR
    A[Running API] --> B[OpenAPI / Swagger]
    B --> C[green-api-auto-discover.py]
    C --> D[Endpoint discovery]
    C --> E[HTTP measurements]
    C --> F[Rule calculation]
    D --> G[JSON report]
    E --> G
    F --> G
    G --> H[HTML dashboard]
    G --> I[Markdown dashboard]

The green-score-analyzer_withdiscovery.sh wrapper orchestrates the run; calculation is centralized in green-api-auto-discover.py.

What is measured for each endpoint

HTTP measurements

HTTP status code, downloaded size, total time, and download speed

Call context

OpenAPI parameters, payload examples, bearer token, and configured repetitions

Network energy

size / GB × network kWh, with a configurable value

Server energy

duration × server power / 3600, then converted to CO₂

Measurements are then aggregated in auto_discovery.all_measurements and discovered_endpoints.

How scores are calculated

API Green Score

Each rule is evaluated on discovered endpoints: pagination, filtering, compression, caching, delta, range, and binary formats

Architecture

AR01 to AR05 add event-driven signals, runtime proximity, single API, autoscaling, and cloud footprint

1. API Green Score = Sum of validated points
2. API Green Score = score converted to A+ / A / B / C / D / E
3. Creedengo score = (1 - violated rules / analyzed rules) × 100

The API Green Score and Creedengo score remain separate: running API on one side, source-code eco-design quality on the other

Where do the Green measurements come from?

The Shift Project

Think tank aiming to inform and influence debate on climate and energy challenges

ADEME

Agency for ecological transition, firmly committed to fighting climate change and resource degradation

Green Software Foundation

Reference for the Software Carbon Intensity (SCI) specification, which structures software impact estimation

Green Code Initiative / ecoCode

Community and benchmarks used by Creedengo to link eco-design issues to CPU and memory overhead

EPA

US agency used for educational emissions equivalents: car kilometres and tree absorption
